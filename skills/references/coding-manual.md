# 附录A 社区更新案例知识编码人机协同手册

## A.1 编码目标与基本单位

### A.1.1 编码目标

本研究面向社区更新跨案例比较，将规划文件、项目报告、学术文献及其他来源中的案例叙述转化为结构化、可追溯、可扩展的关系知识，重点记录技术进入社区更新的情境、参与主体、任务、技术能力、行动过程、作用对象及结果。

编码采用人机协同的方式。AI辅助完成材料检索、证据定位、过程整理、事实拆解、关系候选生成及概念映射建议；专家负责来源核验、事实确认、知识编码审校及概念边界判断。

编码结果应满足事实可核验、过程可恢复、结构可比较和判断可追溯的要求。

### A.1.2 编码单位与编号

| 知识单位             | 定义                    | 编号方式              |
| ---------------- | --------------------- | ----------------- |
| 原始材料 Material    | 具有独立来源的文献、报告或网页资料     | M01、M02……         |
| 证据 Evidence      | 从原始材料中定位的事实依据         | M01-E01、M01-E02…… |
| 案例过程 Process     | 根据证据与事件联系重建的过程段落      | C06-P01、C06-P02…… |
| 原子事实 Atomic Fact | 能够独立核验的单项事实陈述         | F001、F002……       |
| 关系 Relation      | 由实体、谓词、限定信息及证据组成的知识单元 | R001、R002……       |

各类编号在所属案例内分别管理。原子事实可设置独立编号；未单独编号的事实，应通过过程段落及关系编号建立追溯索引。

原始材料、证据、过程段落、原子事实与关系之间允许建立一对多或多对多的关联。证据编号按照材料及片段组织，案例过程按照事件联系和时间顺序组织。

## A.2 案例知识编码规范

### A.2.1 核心知识对象

案例知识采用八类核心实体，构成不同案例的共同分析框架。实体类别依据对象在具体事实与关系中的语义角色确定。

| 类别            | 操作定义                    | 分类边界         |
| ------------- | ----------------------- | ------------ |
| 情境 Context    | 影响更新过程的环境、社会、制度及技术条件    | 区别于具体行动和更新目标 |
| 主体 Actor      | 参与、决策、实施或使用相关技术与资源的人及组织 | 依据具体事实中的角色判断 |
| 任务 Task       | 案例拟解决的问题或希望实现的更新目标      | 区别于具体实施行动    |
| 技术 Technology | 被采用、开发或部署的设备、工具、平台与系统   | 区别于技术提供的能力   |
| 能力 Capability | 技术能够提供或在实践中发挥的具体功能      | 区别于实际行动和结果   |
| 行动 Action     | 主体已经实施或计划实施的具体活动        | 区别于任务和结果     |
| 作用对象 Target   | 被观察、处理、服务或改变的人、物、数据与空间  | 依据关系中的语义角色判断 |
| 结果 Outcome    | 具有证据依据的产出、变化及后果         | 区别于预期效果和行动目标 |

同一对象可以在不同事实中承担不同的语义角色。编码时应检查对象的实际身份与关系中的作用，避免仅依据实体名称或句法位置确定类别。

### A.2.2 原子事实与关系表达

原子事实应具有明确、完整且能够独立核验的事实含义。

关系知识采用以下形式：

**头实体（类别）—关系谓词→尾实体（类别）**

编码遵循以下原则：

1. **事实完整：** 保留事实所必需的主体、行动、对象及关键限定。
2. **粒度适当：** 独立事实分别记录，避免多个事实不合理合并或同一事实过度拆分。
3. **语义准确：** 谓词与方向准确反映证据内容，不增加未经证实的因果判断。
4. **关系开放：** 不预设封闭的关系谓词及方向清单，允许依据案例内容形成新的关系表达。
5. **来源明确：** 每条关系均应关联相应的案例过程及证据依据。

同一事实具有多个来源时，应建立多个证据关联。语义相同的重复陈述原则上归并，具有独立意义的关系予以保留。

知识网络允许存在具有独立证据价值的孤立关系，不强制所有节点连通。

### A.2.3 事实状态与限定信息

每条关系应记录事实状态，并根据需要补充时间、空间、数量和适用范围。

| 状态    | 判定标准                          |
| ----- | ----------------------------- |
| 已实施   | 相关事件已经发生，或所述事实状态具有明确依据        |
| 计划    | 已提出目标、方案或拟开展活动，尚无对应实施依据       |
| 观点/报道 | 来源表达判断、评价或报道性效果陈述，尚不足以确认更强的结论 |
| 争议    | 不同来源存在尚未解决的重要事实冲突             |
| 未确认   | 现有材料不足以确认相关事实或其状态             |

同一对象在不同时期的计划、实施和结果应分别记录。计划规模、试点范围及最终成果应保留对应的时间和数量限定。

缺少证据的内容保持未确认状态，不推定其已经发生或未曾发生。

### A.2.4 开放知识结构与共享概念

案例知识采用可扩展的知识结构。

**（1）稳定的实体类型**

八类核心实体作为知识组织的基本类别，在不同案例中保持一致。

**（2）开放的原生概念与关系**

每个案例从证据中识别原生概念，保留具体对象、事件和活动的原始语义。具体概念、关系谓词及属性允许根据案例内容扩展，不要求不同案例采用相同名称或固定的关系方向。

**（3）共享概念归纳**

共享概念依据不同案例的原生知识逐步形成。通常应有至少两个案例中的原生实例提供语义支持，才能确认为跨案例共享概念。

仅出现于一个案例的概念予以保留，可作为后续映射的候选概念。

**（4）概念映射**

原生概念与共享概念之间可以建立以下映射：

| 映射类型    | 判定依据                | 处理方式           |
| ------- | ------------------- | -------------- |
| 语义等同    | 名称不同但所指及语义范围一致      | 建立同义对应         |
| 原生为下位   | 原生概念属于共享概念的明确下位范围   | 建立上下位映射，保留原生特征 |
| 部分或近似映射 | 复合概念中的特定语义成分与共享概念对应 | 仅映射相关成分，保留其余内容 |
| 暂不映射    | 现有共享概念无法准确覆盖原生语义    | 保留原生概念，进入后续复核  |

映射应记录原生概念、所属案例、实体类别、共享概念、映射类型、语义依据、适用范围及来源位置。

**（5）增量更新**

新案例进入时，应检查原生概念与现有共享概念的对应关系。需要新增或调整共享概念时，同步检查已有案例映射，更新共享网络及版本记录。

复合节点仅部分映射至共享概念时，不得将原生节点的全部属性和关系自动归入共享概念。关系能否参与跨案例分析，应根据其具体语义范围核对。

## A.3 人机协同编码与专家审校流程

### A.3.1 操作流程

案例知识构建依次开展材料整理、证据提取、过程重建、事实拆解、关系编码和专家审校，并通过概念映射与知识网络增量更新实现跨案例积累。

各环节的AI输出作为候选内容，由专家进行相应的核查与确认。

| 环节        | AI辅助任务             | 专家操作                 | 输出          |
| --------- | ------------------ | -------------------- | ----------- |
| 材料整理      | 检索材料，提取来源信息与摘要     | 核查来源、相关性及覆盖范围，确认纳入材料 | Mxx材料登记表    |
| 证据提取      | 定位文本，生成证据陈述及原文线索   | 核对原文，修订表述，补充或排除证据    | Mxx-Exx证据索引 |
| 过程重建      | 整理事件、时间线及案例过程草稿    | 核查事件顺序、主体关系、状态与来源冲突  | Cxx-Pxx案例过程 |
| 事实拆解      | 识别独立事实及相关知识对象      | 核查事实完整性、粒度和证据覆盖      | 原子事实集合      |
| 关系编码      | 生成实体、关系谓词、方向及限定    | 审核类别、语义、粒度和状态        | Rxxx关系候选    |
| 关系审校      | 辅助识别重复、遗漏及不一致内容    | 接受、修改、删除或补充关系        | 专家审核关系集合    |
| 概念映射与网络更新 | 检索已有概念，提出映射及增量更新建议 | 确认概念复用、新增、语义边界和历史一致性 | 增量知识网络      |

### A.3.2 专家审核操作

专家审核应检查来源有效性、事实依据、实体类别、关系语义、事实粒度、事实状态、时空限定及内容完整性。

根据审核结果执行以下操作：

| 操作  | 适用情况                    | 处理要求        |
| --- | ----------------------- | ----------- |
| 接受  | 候选符合编码规则且证据充分           | 保留候选内容      |
| 修改  | 候选基本成立，但事实、分类、语义或限定需要调整 | 保存修改前后内容及原因 |
| 删除  | 证据不足、事实不成立、推断不当或内容重复    | 排除候选并保留删除记录 |
| 待讨论 | 存在暂时无法解决的证据或判断分歧        | 记录争议，暂缓确认   |
| 补充  | 发现遗漏的材料、证据、事实或关系        | 新增记录并关联来源   |

专家完成逐条审核后，应回顾完整案例材料及过程文本，检查遗漏事实、重复编码及不合理的关系表达。

所有审核操作保留原始候选、专家判断和修改版本，不覆盖历史记录。

### A.3.3 双专家对齐与协商裁定

采用双专家审核时，两名专家分别保存独立审核结果。

双方结果以事实语义组（Fact Group）为单位对齐，依据证据、事实内容、主体、行动、作用对象及时间范围识别对应关系，允许一对一、一对多、多对一及无对应关系。

重点检查以下差异：

- 事实选择与内容覆盖；
- 实体类别及角色；
- 关系谓词与方向；
- 事实粒度；
- 事实状态与时空限定；
- 证据依据与事实边界。

对存在分歧的事实组进行协商，确定保留、修改、拆分、合并或删除的关系内容。裁定结果应保存双方原始版本、事实组、处理决定及最终关系。

未完成裁定或质量核查的关系，不纳入最终冻结参考集合。

### A.3.4 共享概念与知识网络的逐案更新

共享概念映射与知识网络扩展作为连续的增量操作进行。每完成一个案例的关系审校，即按照以下步骤更新知识结构。

| 操作       | 具体要求                        |
| -------- | --------------------------- |
| ① 保留原生知识 | 导入本案例已确认的实体、关系、属性及证据指针      |
| ② 检索已有概念 | 在相同实体类别下查找语义等同、上下位或部分对应的概念  |
| ③ 确认概念映射 | 由专家审核映射范围，决定复用、保留单案例概念或新增候选 |
| ④ 更新知识网络 | 将确认后的映射关系与新案例关系纳入共享网络       |
| ⑤ 回查历史映射 | 检查新概念及关系是否影响此前案例的分类和映射边界    |
| ⑥ 保存更新版本 | 记录概念、关系和映射变化及其审核依据          |

每次增量更新应保留案例原生知识及原有证据，不直接以共享概念覆盖原生节点。

共享概念应随案例积累逐步形成和修订。概念出现频率、覆盖案例及关系位置可以作为后续跨案例比较的依据，但不得以提高概念重合度为目的进行不恰当归并。

### A.3.5 知识版本与交付

每个案例应保存以下成果：

| 成果     | 主要内容                 |
| ------ | -------------------- |
| 材料登记表  | 材料编号、名称、来源及链接        |
| 证据索引表  | 证据编号、证据陈述及原文线索       |
| 案例过程   | 时间线、过程段落及证据引用        |
| 原子事实记录 | 事实内容及关联证据            |
| 关系数据表  | 实体、谓词、事实状态、时空限定及证据   |
| 审核记录   | 初始候选、审核动作、修改版本及裁定    |
| 概念映射表  | 原生概念、共享概念、映射类型、依据及版本 |
| 知识网络   | 节点、关系、属性、来源及历史映射     |

原始材料、AI候选、专家审核及协商裁定版本分别保存，确保知识形成过程可以追溯和复核。

## A.4 人机协同操作示范：Damp Busters

### A.4.1 原始材料登记

**案例编号：** C06

**案例名称：** Damp Busters

**材料编号：** M01

**材料名称：** *A City in Common: Explorations on Sustained Community Engagement with Bottom-up Civic Technologies*

**原文链接：** [https://discovery.ucl.ac.uk/id/eprint/1547540/](https://discovery.ucl.ac.uk/id/eprint/1547540/)

**AI辅助：** 提取材料标题、来源信息及与社区问题识别有关的内容。

**专家操作：** 核查材料来源、内容相关性及研究适用范围，确认材料登记信息。

**输出：** M01材料记录。

### A.4.2 证据提取与确认

**证据编号：** M01-E03

**证据陈述：** Damp Busters的问题识别阶段持续约4个月，包括城市网络分析、社区组织联系和艺术家在居民日常活动空间开展的非正式交流。

**原文线索：** M01，第215—218页。

**AI辅助：** 定位原文，提取相关事实并生成证据陈述。

**专家操作：** 核对原始文本，检查时间信息、活动内容及主体表达，确认或修订证据陈述。

**输出：** M01-E03证据记录。

### A.4.3 案例过程重建

**过程编号：** C06-P01

**过程内容：** 社区问题识别与居民意见收集。

根据相关证据，整理项目团队通过社区网络分析、地方组织联系及非正式交流识别社区问题的过程。

**AI辅助：** 组织关键事件与过程叙述，关联证据编号。

**专家操作：** 核查事件顺序、主体关系及证据支持情况，修订过程表述。

**输出：** 带有证据索引的C06-P01过程段落。

### A.4.4 原子事实与关系候选

从相关过程内容中识别以下事实：

| 事实编号 | 事实内容           |

| F002 | 项目联系地方社区组织     |

**AI辅助：** 拆解事实，识别知识对象，生成关系候选。

### A.4.6 原生概念映射与知识网络更新

专家审核后的实体形成原生知识节点，关系谓词形成有向边，过程位置、事实状态及证据依据作为关联信息保存。

本次审校形成以下局部关系结构：

- 项目团队 —开展→ 社区居民意见收集
- 社区居民意见收集 —采用→ 社区会议、地方组织联系与社区网络分析
- 项目团队 —邀请参与→ 艺术家
- 艺术家 —开展→ 与居民的非正式交流

**AI辅助：** 整理原生节点与关系，检索相同类别下已有的共享概念，提出映射候选。

**专家操作：** 核查概念语义与映射范围，确认复用、新增或保留单案例概念，并检查历史映射一致性。

Damp Busters中的原生概念“延迟技术语言并设置术语提示机制”（行动）可映射至共享概念“参与表达方式调整与转译”（SC-X29）。该映射保留原生行动的具体形式，不将不同案例中的技术参与方式视为完全相同。

经确认的原生概念、共享概念及其关系共同进入增量知识网络，保留相应过程位置与证据索引。

### A.4.7 操作注意事项

**（1）来源与证据核验。** 原始材料登记和证据提取均需核查来源。无法取得原始材料或不能定位证据的内容，应记录核验状态，不作为已核实证据使用。

**（2）编号关联。** Mxx-Exx、Cxx-Pxx及Rxxx分别对应证据、过程与关系。各编号不要求一一对应，应根据实际事实建立来源关联。

**（3）主体与作用对象重复。** 同一对象在不同关系中可能分别作为行动主体与作用对象。例如，社区居民可以参与问题识别，也可以成为社区调查的对象。应分别保留具有独立事实依据的关系，并检查两种表述是否指向同一实际对象。

同一对象不应仅因角色不同而被误认为两个互不相关的实体。若知识结构支持多重类别或角色标注，可保留共同的实体身份及其不同角色；若按类别分别建立节点，应记录两者的同一指称关系。具有不同身份或范围的对象不得仅因名称相似而合并。

**（4）技术、能力与行动区分。** Frogbox属于技术，温湿度采集属于能力，居民使用设备记录室内环境属于行动。技术具备某种能力，不代表该能力已经进入实际使用。

**（5）事实粒度。** 对包含多个独立事实的候选关系进行必要拆分，保留行动主体、实施内容及作用对象的完整含义。相同事实的重复表达原则上归并，不为增加关系数量而拆分。

**（6）事实状态与作用边界。** 严格区分计划、实施、报道与未确认内容。技术试验规模、社区参与规模及最终成果分别记录，不以技术能力或预期目标推定实际效果。

**（7）共享概念的逐案形成。** 一个案例中出现的新概念首先作为原生概念保留。后续案例出现具有共同语义范围的概念时，再提出共享概念候选，经专家确认后纳入共享体系。单案例概念不强制映射至已有概念。

**（8）复合概念与部分映射。** 原生概念包含多个语义成分时，仅将有明确依据的部分映射至共享概念。其余内容保留原生表达，不自动继承共享概念的全部关系和属性。

**（9）增量网络与历史一致性。** 新案例加入后，应同步检查共享概念复用、关系更新及历史映射。修改概念边界时，应回查受影响的已有案例，不直接覆盖原生节点和历史关系。

**（10）审校与版本管理。** 保留AI初始候选、专家审核、修改及裁定记录。单专家审核完成后，按照研究要求进入后续复核或双专家裁定程序。
