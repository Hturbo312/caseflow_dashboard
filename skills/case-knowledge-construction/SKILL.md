# 案例知识构建

## 目标

把一个社区更新事件的多源材料，转化为可核验、可恢复、可比较、可追溯的案例知识包。案例单位是「一次社区更新事件的完整过程」。

## 输入

- 原始材料：规划文件、项目报告、学术文献、网页资料、访谈或图片。
- 案例编号与名称。
- 研究问题；如尚未确定，在 G0 与研究者确认。
- 编码手册：`../references/coding-manual.md`，重点 A.1–A.3.5；示例见 A.4。共享契约：`../contracts/case-knowledge-contract.md`、`../contracts/review-packet.md`。

## 核心规则

- 所有 AI 输出都是候选；研究者确认后才冻结。
- 每个 gate 输出 `review_packet` 后必须停止，不得自动进入下一阶段。
- 事实状态严格使用手册五类：已实施、计划、观点/报道、争议、未确认。
- 关系谓词开放，不预设封闭清单；基础关系表不写未经证实的因果判断。
- 不强制知识网络连通；有独立证据价值的孤立关系可以保留。
- 同一对象可在不同关系中承担不同角色；不得仅因名称相似而合并不同身份或范围的对象。
- 技术、能力、行动必须区分：技术具备某种能力，不代表该能力已进入实际使用。
- 本 skill 只产原生知识和共享概念候选；不确认正式共享概念。

## 流程

图中的五阶段在执行时拆成 G1–G6 六个确认点（关系编码与关系审校分开），另加 G0 案例边界。

### G0 案例边界

- 智能体：提出事件名称、起止时间、涉及范围、排除项、证据截止时间和研究问题草案。
- 研究者：确认案例边界与纳入/排除标准。
- 输出：`case_scope.md`。

### G1 材料整理

- 智能体：检索材料，提取标题、来源、作者、日期、链接、摘要和相关范围。
- 研究者：核查来源、相关性、覆盖范围，确认纳入材料。
- 输出：`Mxx` 材料登记表。

### G2 证据提取

- 智能体：定位原文，生成证据陈述和原文线索。
- 研究者：核对原文、修订表述、补充或排除证据。
- 输出：`Mxx-Exx` 证据索引。

### G3 过程重建

- 智能体：整理事件、时间线、过程段落草稿，并关联证据。
- 研究者：核查事件顺序、主体关系、状态变化和来源冲突。
- 输出：`Cxx-Pxx` 案例过程。

### G4 事实拆解

- 智能体：识别独立事实、实体及其语义角色。
- 研究者：核查事实完整性、粒度、证据覆盖和限定信息。
- 输出：`Fxxx` 原子事实集合。

### G5 关系编码

- 智能体：生成实体类别、关系谓词、方向、事实状态及时空/数量限定。
- 研究者：审核类别、语义、粒度和状态。
- 输出：`Rxxx` 关系候选。

### G6 关系审校

- 智能体：辅助识别重复、遗漏、矛盾和方向错误。
- 研究者：接受、修改、删除、待讨论或补充。
- 输出：冻结关系集合 + 审核记录。
- 完成审校后，回顾完整材料和过程文本，检查遗漏事实、重复编码和不合理关系。

## 交付物

- 材料登记表
- 证据索引表
- 案例过程
- 原子事实记录
- 关系数据表
- 审核记录
- `case_pack` 清单：原生实体、关系、概念候选、证据指针和未决问题

## 交接

向 `scalable-concept-framework` 交接：原生节点、关系、原生概念、证据指针、审核记录和未决问题。不要在本 skill 内确认共享概念。

## 禁止

- 不把计划、观点或报道写成已实施事实；不把未经证实的因果判断写入关系表。
- 不因实体名称相似而合并不同对象；不为增加关系数量而过度拆分事实。
- 不覆盖历史版本或审核记录。
