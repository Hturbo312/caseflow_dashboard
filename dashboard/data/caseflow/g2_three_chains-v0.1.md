# 三组连续性论证（G2→G3）

生成日期：2026-11-13
状态：**三组均为候选链，段落内可自洽，跨组尚未合并为结论**。

---

## 0. 怎么用

每组是一条 4 步链（P1→P2→P3→P4）。**必须按顺序核**：P1 不成立，整组作废；P3 不成立，P4 改写成弱版本。

每组末尾给"该组可独立成立的结论"，跨组汇总在 §5。所有"→"都是条件句。

**先纠正我上一版一处错误**：C12 我写过"组织清算 → 服务终止"，这是过度断言。库里 C12-P07 的过程状态是 `frozen`、标题为"品牌退出、壳公司解散与服务终止未确认"；关系表里 `CityServe (999) Ltd → CityServe 业务（2014）` 的 `legal_continuity_with` 标的是 `unconfirmed`。正确读法是：**壳公司清算解散，业务被 ITS 收购，服务是否延续无记录**。这个纠正直接影响组一的 P3。

## 1. 总链条

三组不是并列的三个案例对，而是同一个变量的三种形态：

| | 承接对象 | 承接主体形态 | 该组解释什么 |
|---|---|---|---|
| 组一 C12×C16 | 网络资产 | **一个法人** | 谁能持有它、持有后还看不看得见 |
| 组二 C10×C11 | 住宅改造工程 | **一群产权人** | 多少产权单元能被决策规则放行 |
| 组三 C19×C20 | 参与产出 | **一张行动清单** | 产出要拆到多细才有人接 |

递进关系：承接主体从"单一法人"退化到"产权集合"，再退化到"尚未确定"；每退一步，就多一个能解释落地差异的变量。

## 2. 组一｜C12 Eastserve × C16 Red Hook WiFi

**为什么可比**：都是社区无线/宽带，都是"项目 → 可运营资产"，都有明确的结束期与移交动作。技术族相同，可以控制住"技术差异"。

### P1 技术都达到了可用状态

| 证据 | 看什么 |
|---|---|
| C12-M20-E01 | ITS 收购后推出 36Mbps 固定无线，覆盖 25km²、48,000 户 |
| C12-M11-E02 | 超 5,500 名居民获补贴电脑并受训；1,500+ 付费宽带用户 |
| C16-M15-E10 | 2019 年移交时网络仍在运行，Sky Packets 承担月约 3,000 美元成本 |
| 关系 `C16 → 覆盖 Red Hook 社区` | 覆盖成立 |

判真：两案在移交/转手时技术都是可用的。
判假：C12 的 36Mbps 属收购方新业务、与原社区网络无关。

### P2 两者都把资产交给了另一个主体

| 证据 | 看什么 |
|---|---|
| 关系 `Symera Eastserve Ltd → operates → Eastserve` | 第一任运营主体 |
| 关系 `CityServe (999) Ltd → enters_liquidation`、`→ dissolves` | 第二任清算解散 |
| 关系 `ITS Technology Group → acquires → CityServe 业务（2014）` | 业务被收购 |
| 关系 `CityServe 业务（2014）→ operates → eastserve.com 门户` | 收购后仍在运营门户 |
| C16-M15-E10 | RHI 于 2019 年将网络移交 Sky Packets |

判真：两案都发生了主体更替，且都不是"项目结束即关停"。
判假：C12 的收购标的与 Eastserve 无关，或 C16 移交只是名义。

### P3 结局差异与承接主体的**性质**同向变化，且首先体现在"可观测性"上

| 证据 | 看什么 |
|---|---|
| C12-P07（过程） | 状态 `frozen`，标题即"服务终止**未确认**" |
| 关系 `legal_continuity_with` = `unconfirmed` | 收购标的是否承接原服务，未确认 |
| C16-M15-E09 | 2016 Smith 离开、2017 Schloss 离开，维护人员所剩无几 |
| C16-M15-E12 | 2023 年约剩 10 个活跃站点，Coffey Park 已不在其中 |
| C16-M02-E12 | 明确写出"必须有本地支持结构与知识传递，否则知识源离开后网络会崩溃" |

读法：C12 走的是**市场化转手**（公司法人在市场上被收购），结果只剩下工商登记可查，服务状态不可追踪；C16 走的是**非营利移交**（RHI → Sky Packets），留下了月成本、站点数、人员变动三类可核查记录，收缩因此可量化（峰值约 20 → 2023 年约 10）。

判真：C12 确实找不到 2014 年后的服务状态记录，而 C16 能找到连续记录。
判假：C12 有 ITS 之后的用户数或关停公告。

### P4 因此"留存"不是一个事实，而是承接结构的函数——首先取决于承接方是否留下运营记录

**该组可独立成立的结论**：

> 同一技术族在项目期结束后都会易手；易手之后能否判定"还在不在"，取决于接盘方是市场化法人还是留下运营台账的机构。**留存的可观测性差异，本身是承接结构差异的一部分，不是数据缺失。**

这条结论有方法论价值：它说明为什么 C12 在库里只能写成"未确认"，而 C16 能写成"约 10 个站点"——不是编码偷懒，是对象性质决定的。

## 3. 组二｜C10 Tartu × C11 Vitoria-Gasteiz

**为什么可比**：同属 EU SmartEnCity，同一技术族（外保温 + 区域供热 + 智能表计），同一制度前提（私人产权、业主协会集体决策）。这是全库唯一"项目设计被控制住"的一对。

### P1 技术方案与项目设计高度同构，可控制住"技术差异"

| 证据 | 看什么 |
|---|---|
| C10-M16-E02 | 试点区 0.39km²、43 栋 Khrushchyovka、1,779 套 |
| C10-G03-Q01 | 每栋公寓楼由相应业主协会组织管理，私人产权 |
| C11-G07-Q01 | 改造须取得业主共同体同意 |
| C10-M16-E05 / C11 融资结构 | 均为 H2020 + 地方 + 业主融资组合 |

判真：两案的技术菜单与资金结构同源。
判假：C10 的 smart-home 与 C11 的供热改造不属同一技术族。

### P2 决策门槛决定"进入规模"，而不是技术决定

| 证据 | 看什么 |
|---|---|
| C10-G03-Q02 | 市政府能推动、能给补助，但**无法单方面决定**私人住宅是否改造 |
| C10-G06-Q01 | 2017 年 22 个协会加入，全部进入设计 |
| C10-G10-Q01 | 2018 年统计口径 21 栋 → 2019 年稳定为 17 栋 |
| C10-G14-Q01 | 2021 年 Turu 17 完成后由 17 增至 18 栋 |
| C11-G07-Q02 | 2017-09，108 个共同体中**仅 3 个**正式加入 |
| C11-G11-Q01 | 延长决策期后扩至 144 个共同体、1,873 套 |
| C11-G13-Q01 | 2019 年部分退出，实际降至 312 套 |
| C11-G16-Q01 | 最终 26 个共同体、302 套完成 |

读法：C10 的漏斗是 22 协会 → 18 栋（约 82% 转化）；C11 的漏斗是 108 共同体 → 3 加入 → 扩到 1,873 套 → 降到 312 套 → 最终 302 套（约为峰值的 16%）。**同样的技术，进入率差 5 倍。**

判真：两案的数字链条都能在证据里逐一对应。
判假：C11 的 312 与 302 是不同统计口径而非退出。

### P3 决定门槛高低的是成本分摊规则，不是技术方案

| 证据 | 看什么 |
|---|---|
| C11-G08-Q01 | 居民顾虑集中在费用、供热收费、产权决策、长期收益与实施风险 |
| C11-G08-Q02 | **原有区域供热收费制度**被视为是否加入的重要因素 |
| C11-G10-Q01 | 改为"住宅独立计费或共同体统一计费"可选，并延长加入期限 |
| C11-G12-Q01 | 增加业主会议、咨询与入户访问解释收费 |
| C10-G04-Q02 | 公共资金与融资安排需协调技术方案、补助与居民承担能力 |
| C10-M16-E06 | 协会大会决定参与、贷款、设计、施工等重大事项 |

读法：C11 的转折点不是技术优化，而是**把统一收费改成可选计费**；此后加入范围才从 3 个扩到 144 个。C10 靠的是补助 + 业主贷款的分摊组合。

判真：收费规则调整发生在范围扩大之前，且材料把两者联系起来。
判假：范围扩大主要由补贴额度提高或政策强制推动。

### P4 技术决定"改得好不好"，产权结构决定"改多少"

| 证据 | 看什么 |
|---|---|
| C10-M25-E01 | 18 栋终期实际能源使用下降约 **37%** |
| C10-G11-Q01 | 实体改造完成后，smart-home 仍在安装调试 |
| C11-G18-Q01 | 热能需求 **-50%**、总能耗 **-36%**、CO₂ **-54%** |
| C11-G18-Q02 | 能源账单下降约 15%–20% |

读法：两案的**改造后成效几乎一致**（-36% vs -37%），但**改造规模差一个量级**（18 栋/664 套 vs 26 共同体/302 套，且起点是 1,873 套）。成效由技术决定，规模由产权与收费规则决定。

**该组可独立成立的结论**：

> 在私人产权 + 业主集体决策的条件下，同一技术方案的落地规模主要由"成本分摊规则能否被业主接受"决定，技术只决定改造后的成效强度。二者的变异来源不同，不能用一个指标同时衡量。

这条结论直接可用的推论：评估这类项目时，"节能率"和"覆盖率"必须分开报告，合并成一个"成效"会掩盖真正的约束点。

## 4. 组三｜C19 Connect EC × C20 普里什蒂纳

| 证据 | 看什么 |

## 5. 三组怎么串成一条

| 步 | 命题 | 来自 |
|---|---|---|
| S1 | 技术可用性不是留存或落地的解释项（三组 P1 全部排除技术差异） | 组一 P1 + 组二 P1 + 组三 P1 |
| S2 | 承接主体的性质决定留存**形态**，并首先决定"能否被观测" | 组一 P3–P4 |
| S3 | 当承接主体是一群产权人时，**决策规则**（尤其成本分摊）决定进入规模 | 组二 P2–P3 |
| S4 | 当承接主体尚未确定时，**产出颗粒度**决定可实施性 | 组三 P2–P3 |
| S5 | 技术只决定**成效强度**，不决定规模与留存 | 组二 P4 + 组一 P1 + 组三 P1 |

合成机制假设（hypothesis，尚不可称 conclusion）：

> **数字/技术介入的落地与留存，由"承接"这一环节决定，而技术本身只决定成效强度。承接越是落在单一法人身上，留存越依赖该法人的存续与记录能力；越是落在产权集合上，规模越依赖分摊规则的通过率；越是尚未落到任何主体，产出就必须被拆到可被单笔资金、单个主体承接的粒度。三种形态对应三个不同的失败点，因此不能用同一套指标（覆盖率、节能率、参与人数）去衡量。**

这条假设的价值在于：它把"为什么很多项目期结束后就说不清"从道德判断（没人管）变成了结构判断（承接形态决定了可观测性）。
